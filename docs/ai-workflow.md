# AI 工作流程文档

## 📋 概述

本文档记录了我在项目开发中的标准化工作流程，用于确保任务开发的一致性、高效性和质量。

## 🔄 标准工作流程

### 1. 阅读任务需求
```
✅ 步骤：读取 task.md 文件
📁 文件位置：/Users/achen/Priv/task-banner/docs/task.md
🎯 目标：理解任务需求、优先级和技术要点
📝 关键动作：
- 仔细阅读任务描述
- 理解状态和优先级
- 明确具体需求点
- 记录 task-id
```

### 2. 需求澄清和确认
```
✅ 步骤：与用户确认理解
🎯 目标：确保需求理解准确，避免偏差
📝 关键动作：
- 总结理解的内容
- 提出确认问题
- 等待用户确认
- 根据反馈调整理解
```

### 3. 制定开发计划
```
✅ 步骤：创建 TodoList
🛠️ 工具：TodoWrite 工具
🎯 目标：拆分任务，制定可执行的开发步骤
📝 关键动作：
- 拆分任务为具体步骤
- 设置优先级和状态
- 使用进度跟踪
```

### 4. 分析现有代码
```
✅ 步骤：阅读相关文件
📁 工具：Read、Grep、Glob 工具
🎯 目标：了解现有实现，避免重复工作
📝 关键动作：
- 定位相关组件文件
- 分析现有代码结构
- 理解数据流和状态管理
- 识别需要修改的地方
```

### 5. 开始开发实现
```
✅ 步骤：编码实现
🛠️ 工具：Edit、Write 工具
🎯 目标：按计划实现功能需求
📝 关键动作：
- 按照TodoList逐步实现
- 更新TodoList状态（pending→in_progress→completed）
- 代码修改时保持类型安全
- 添加必要的注释
```

### 6. 验证开发结果
```
✅ 步骤：功能验证
🛠️ 工具：Bash（构建测试）、开发服务器、Chrome DevTools MCP
🎯 目标：确保功能正常工作
📝 关键动作：
- 运行构建测试：npm run build
- 启动开发服务器：cd frontend && npm run dev
- 手动测试关键功能
- 检查热更新是否正常
- 使用 Chrome DevTools MCP 深度调试
```

### 7. Chrome DevTools 深度调试
```
✅ 步骤：浏览器端调试和分析
🛠️ 工具：Chrome DevTools MCP (chrome-devtools)
🎯 目标：深度调试前端功能，分析运行时问题
📝 关键动作：
- 检查页面元素和样式
- 监控网络请求和响应
- 分析 JavaScript 控制台错误
- 检查本地存储和会话数据
- 性能分析和内存检查
- 验证 DOM 结构和事件绑定
```

### 8. TypeScript 错误修复
```
✅ 步骤：类型检查和修复
🛠️ 工具：TypeScript 编译器
🎯 目标：确保代码类型安全，构建无错误
📝 关键动作：
- 查看TypeScript错误信息
- 修复类型定义问题
- 处理组件引用问题
- 确保构建成功
```

### 9. 更新任务文档
```
✅ 步骤：更新 task.md
📁 文件位置：/Users/achen/Priv/task-banner/docs/task.md
🎯 目标：记录完成情况，保持文档同步
📝 关键动作：
- 更新任务状态：待办 → 待验收
- 添加任务摘要（20-50字）
- 更新解决方案内容
- 更新验证结果
- 保留 task-id 注释
- 更新导出时间
```

### 10. 生成 task.json
```
✅ 步骤：创建/更新 task.json
📁 文件位置：/Users/achen/Priv/task-banner/docs/task.json
🛠️ 工具：Write 工具
🎯 目标：生成结构化任务数据
📝 关键动作：
- 创建JSON格式任务记录
- 包含_id、status、summary、content字段
- content字段使用 \n 转义换行
- 单任务用对象，多任务用数组
```

### 11. 发送完成通知
```
✅ 步骤：通知任务完成
🛠️ 工具：Bash + 通知脚本
📁 脚本位置：/Users/achen/Priv/task-banner/.claude-notify.sh
🎯 目标：及时通知用户任务完成
📝 关键动作：
bash /Users/achen/Priv/task-banner/.claude-notify.sh "标题" "描述"
- 标题：简短任务完成说明（如：✅ XXX 功能完成）
- 描述：一句话总结完成内容
```

## 🛠️ 常用工具使用指南

### 文件操作工具
- **Read**：读取文件内容
- **Write**：创建/覆盖文件
- **Edit**：精确替换文件内容
- **Glob**：文件模式匹配
- **Grep**：内容搜索

### 开发工具
- **Bash**：命令行操作（构建、测试、启动服务器）
- **TodoWrite**：任务进度跟踪

### 调试分析工具
- **Chrome DevTools MCP (chrome-devtools)**：Chrome DevTools MCP 工具，用于调试和分析 Chrome 浏览器
  - **元素检查**：检查页面DOM结构、CSS样式和布局
  - **网络监控**：监控API请求、响应时间和状态码
  - **控制台分析**：查看JavaScript错误、警告和日志
  - **存储检查**：检查localStorage、sessionStorage、cookies等
  - **性能分析**：分析页面加载性能、内存使用情况
  - **事件监听**：检查事件绑定和触发情况

### Chrome DevTools MCP 使用场景
```
✅ 前端功能调试
- 检查组件渲染状态
- 验证样式和布局正确性
- 监控状态变化和响应

✅ API 调试
- 检查请求参数和响应数据
- 分析网络错误和超时问题
- 验证接口调用逻辑

✅ 性能优化
- 分析页面加载时间
- 检查内存泄漏问题
- 优化资源加载策略

✅ 问题排查
- 定位JavaScript运行时错误
- 检查数据绑定和状态同步
- 验证用户交互流程
```

### 搜索和分析工具
- **Grep**：代码搜索，支持正则表达式
- **Glob**：文件路径模式匹配
- **Task**：复杂搜索和分析任务

## 🎯 任务摘要编写规范

### 长度要求
- **字数范围**：20-50 字
- **内容重点**：用一句话概括完成的内容和解决的问题

### 好的示例
- ✅ "实现了用户登录功能，支持账号密码和第三方登录"
- ✅ "修复了任务列表排序 bug，优化了性能"
- ✅ "添加了任务导出功能，支持 Markdown 格式"
- ✅ "将文档列表从浮动布局改为同级分栏布局，提升用户体验"

### 避免的示例
- ❌ "将描述从 xxx 改为 xxx"（太粗暴）
- ❌ "已在 Service 层实现..."（太技术化）
- ❌ "修复了bug"（太模糊）

## ⚠️ 重要提醒事项

### 必须保留的内容
- **task-id 注释**：这是任务回填的关键标识
- **Markdown 结构完整性**：不要删除任何标题层级
- **功能验证结果**：记录测试结果和发现的问题

### 开发注意事项
- **渐进式开发**：先实现核心功能，再优化细节
- **类型安全**：确保 TypeScript 代码无错误
- **向后兼容**：修改时不破坏现有功能
- **用户反馈**：及时响应用户的调整需求

### 文档维护
- **及时更新**：每次任务完成后立即更新文档
- **信息准确**：确保文档内容与实际实现一致
- **格式规范**：保持文档格式统一

## 🔄 工作流程优化

### 提升效率的建议
1. **并行操作**：使用多工具调用提高效率
2. **预防性检查**：在开发前先分析潜在问题
3. **及时验证**：每完成一个功能点就验证
4. **文档同步**：边开发边更新文档

### 质量保证
1. **构建验证**：每次修改后检查构建状态
2. **功能测试**：确保新增功能正常工作
3. **类型检查**：保证 TypeScript 代码质量
4. **用户体验**：关注界面交互细节

## 📊 常见任务类型处理模式

### 功能开发类任务
1. 需求分析 → 2. 技术方案 → 3. 编码实现 → 4. 测试验证 → 5. 文档更新

### Bug 修复类任务
1. 问题定位 → 2. 根因分析 → 3. 修复实现 → 4. 回归测试 → 5. 验证关闭

### 界面优化类任务
1. 现状分析 → 2. 设计方案 → 3. 布局调整 → 4. 交互测试 → 5. 体验验证

### 重构优化类任务
1. 代码分析 → 2. 重构设计 → 3. 分步实施 → 4. 功能验证 → 5. 性能测试
