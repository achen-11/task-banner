# 生产环境认证修复说明

## 问题描述

用户反馈：生产环境登录成功后，页面仍然被认为未登录，不断重定向到登录页。

## 问题原因

前端认证逻辑在生产环境依赖 `window.__USER_INFO__`，但该变量需要通过服务端脚本注入。由于缺少 `<script env="server">` 代码，导致：

1. 用户登录成功后，`k.account.isLogin` 为 `true`
2. 但前端无法获取 `window.__USER_INFO__`
3. `isLogin()` 函数返回 `false`
4. 路由守卫触发，重定向到登录页

## 解决方案

### 1. 创建用户服务

**文件**: `kb-task/src/code/Services/user.ts`

提供 `getUserInfo()` 函数，根据用户名获取用户信息：

```typescript
export interface UserInfo {
  id: number
  username: string
  email: string
  displayName: string
  avatar: string
  isAdmin: boolean
}

export function getUserInfo(username: string): UserInfo {
  // TODO: 从数据库查询用户信息
  return {
    id: 1000,
    username: username,
    email: `${username}@example.com`,
    displayName: username,
    avatar: '',
    isAdmin: true
  }
}
```

### 2. 修改 Vite 构建插件

**文件**: `kb-task/frontend/vite.config.ts`

在 `addKoobooUrlPlugin()` 中添加服务端脚本注入逻辑：

```typescript
// 2. 在 <title> 标签后添加服务端脚本
if (!html.includes('env="server"')) {
  const serverScript = `

    <!-- 服务端脚本：检查登录状态并注入用户信息 -->
    <script env="server" type="module">
      import { getUserInfo } from 'code/Services/user'

      // 1. 检查登录状态
      if (!k.account.isLogin) {
        k.response.redirect('/_Admin/login?permission=u&returnurl=/')
        return
      }

      // 2. 获取当前登录用户
      const username = k.account.user.current.userName
      const userInfo = getUserInfo(username)

      // 3. 注入用户信息到客户端
      k.utils.clientJS.setVariable('__USER_INFO__', userInfo)
    </script>`

  html = html.replace('</title>', '</title>' + serverScript)
  console.log('✅ Added server-side authentication script')
}
```

### 3. 构建输出

构建后的 HTML（`kb-task/src/page/index.html`）自动包含：

```html
<!-- @k-url / -->
<!DOCTYPE html>
<html lang="">
  <head>
    <title>Task Flow</title>

    <!-- 服务端脚本：检查登录状态并注入用户信息 -->
    <script env="server" type="module">
      import { getUserInfo } from 'code/Services/user'

      if (!k.account.isLogin) {
        k.response.redirect('/_Admin/login?permission=u&returnurl=/')
        return
      }

      const username = k.account.user.current.userName
      const userInfo = getUserInfo(username)
      k.utils.clientJS.setVariable('__USER_INFO__', userInfo)
    </script>

    <script type="module" src="/index-[hash].js"></script>
  </head>
  <body>
    <div id="app"></div>
  </body>
</html>
```

## 工作流程

### 生产环境（Kooboo）

```
1. 用户访问页面
   ↓
2. Kooboo 服务端执行 <script env="server">
   ↓
3. 检查 k.account.isLogin
   ├─ false → 重定向到 /_Admin/login
   └─ true → 继续
   ↓
4. 获取当前登录用户名：k.account.user.current.userName
   ↓
5. 调用 getUserInfo(username) 获取完整用户信息
   ↓
6. 注入到客户端：window.__USER_INFO__
   ↓
7. 前端 Vue 应用启动
   ↓
8. auth.ts 从 window.__USER_INFO__ 读取用户信息
   ↓
9. 路由守卫检查通过，正常显示页面
```

### 开发环境（Vite）

```
1. 应用启动
   ↓
2. initAuth() 检查 localStorage
   ↓
3. 无 token → devLogin() 自动登录 Mock 用户
   ↓
4. 存储到 localStorage.dev_user
   ↓
5. 后续请求自动添加 Bearer Token
   ↓
6. 无需服务端脚本
```

## 关键点

1. **服务端脚本在构建时注入**
   - 不在源文件 `frontend/index.html` 中
   - 通过 Vite 插件在构建后添加
   - 避免 Vite 在构建时解析报错

2. **环境自动识别**
   - 开发环境：`import.meta.env.DEV === true`，使用 Mock 数据
   - 生产环境：`import.meta.env.DEV === false`，使用 `__USER_INFO__`

3. **用户服务待完善**
   - 当前 `getUserInfo()` 返回基于用户名的 Mock 数据
   - 后续需要对接数据库，查询真实用户信息

## 验证方法

### 开发环境

```bash
cd kb-task/frontend
npm run dev
```

打开浏览器控制台，应该看到：
```
🔧 [Dev Mode] Auto login with mock user
👤 [Dev Mode] Current user: {...}
```

### 生产环境

1. 运行构建：
   ```bash
   cd kb-task/frontend
   npm run build
   ```

2. 检查 `kb-task/src/page/index.html` 是否包含 `<script env="server">`

3. 部署到 Kooboo 后：
   - 访问页面 → 自动重定向到登录页（未登录）
   - 登录成功 → 返回页面，显示用户信息
   - 刷新页面 → 保持登录状态
