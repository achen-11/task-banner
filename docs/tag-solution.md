  标签提示词功能设计方案

  📋 需求概述

  当前状态

  - 标签可以被任务关联（Task.tagIds: string[]）
  - 标签仅用于任务分类和筛选
  - 标签目前只存储 ID，没有完整的标签对象

  新需求

  为标签添加提示词管理功能，在导出任务（Cmd+E）时自动将标签关联的提示词注入到任务描述中，指导 AI 的行为。

  使用场景

  场景 1：讨论型任务
  - 创建标签："讨论"
  - 绑定提示词："这是讨论型任务，你不要操作代码，先将你的想法输出到 md 文件和我讨论"
  - 创建任务，添加"讨论"标签
  - Cmd+E 导出时，提示词自动拼接到任务内容中

  场景 2：重构任务
  - 标签："重构"
  - 提示词："这是重构任务，请保持原有功能不变，优化代码结构和性能，并添加必要的单元测试"

  场景 3：文档任务
  - 标签："文档"
  - 提示词："这是文档任务，不需要编写代码，请专注于输出清晰的文档内容，使用 Markdown 格式"

  4.2 实现逻辑

  export function exportTaskToMarkdown(task: TaskDetail, projectName?: string): string {
    const lines: string[] = []

    // ... 添加 AI 协作指引（保持不变）

    lines.push(`---\n`)
    lines.push(`## 任务列表\n`)

    // ... 任务基本信息

    // ✨ 新增：如果任务有标签且标签有提示词，在描述前注入
    let taskContent = task.content || '暂无描述'

    if (task.tags && task.tags.length > 0) {
      const tagPrompts = task.tags
        .filter(tag => tag.prompt && tag.prompt.trim())
        .map(tag => tag.prompt)

      if (tagPrompts.length > 0) {
        const promptSection = `**📌 标签提示词：**\n\n${tagPrompts.join('\n\n')}\n\n---\n\n`
        taskContent = promptSection + taskContent
      }
    }

    lines.push(`**任务描述：**\n`)
    lines.push(taskContent)

    // ...
  }

  问题 2：多标签提示词冲突

  如果一个任务同时有"讨论"和"重构"标签，两个提示词可能矛盾：
  - "讨论"：不要操作代码
  - "重构"：优化代码结构

  方案 A：按顺序拼接所有提示词
  **📌 标签提示词：**
  1. 这是讨论型任务，你不要操作代码...
  2. 这是重构任务，请保持原有功能不变...

  方案 B：只使用第一个标签的提示词

  方案 C：UI 层面限制，一个任务只能有一个带提示词的标签

  建议：方案 A，允许多个提示词组合，由用户自己判断是否合理 (接受建议)

  ---
  问题 3：标签管理入口位置

  方案 A：项目设置页面（独立路由）
  - 优点：功能独立，不影响现有布局
  - 缺点：入口可能不够显眼

  方案 B：ProjectView 右侧栏（新增 Tab）
  [任务列表] [标签管理] [项目设置]
  - 优点：快速访问
  - 缺点：右侧栏比较拥挤

  方案 C：任务筛选栏右侧按钮
  [筛选器] [排序] [🏷️ 管理标签]
  - 优点：与标签使用场景接近
  - 缺点：入口分散

  建议：方案 B + 快捷入口（在任务筛选栏添加"管理标签"按钮）, 不过不用新增 tab, 现在本身就有标签 tab
