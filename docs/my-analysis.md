# KB-Task 流程改版分析

## 📋 任务理解

### 🎯 核心问题
当前的任务管理流程存在逻辑错误：
- **当前错误流程**：AI 完成的内容导入到任务的 `content` 字段
- **正确流程**：AI 完成的内容应该作为评论保存，形成完整的变更历史

### 🔄 正确的任务管理流程
```
1. 新建任务
   ↓
2. 编辑描述
   ↓
3. 导出任务 (供 AI 处理)
   ↓
4. AI 完成任务
   ↓
5. 导入 AI 结果 → 新建评论 (不是覆盖 content!)
   ↓
6. 如需优化 → 再新建评论
   ↓
7. 导出时 → 导出评论历史 (或其他方式)
```

## 💡 实现方案分析

### 1️⃣ 修改导入方法
**涉及场景**：
- 单任务导入
- 批量导入
- 任务详情页导入

**核心改动**：
```typescript
// 当前逻辑 (错误)
task.content = aiGeneratedContent

// 新逻辑 (正确)
task.comments.push({
  content: aiGeneratedContent,
  type: 'ai_completion',
  createdAt: Date.now()
})
```

**疑问**：
- 如何区分 AI 生成的评论和用户手动评论？
- 是否需要为不同类型的评论设计不同的样式？
- 导入时是否需要检测重复内容？

### 2️⃣ 评论内容展示优化
**需求**：AI 内容通常很长，需要类似"查看详情"的交互

**实现思路**：
```vue
<template>
  <div class="comment-content">
    <div v-if="!showFullContent" class="comment-summary">
      {{ contentSummary }}
      <el-button @click="showFullContent = true">查看详情</el-button>
    </div>
    <div v-else class="comment-full">
      {{ fullContent }}
      <el-button @click="showFullContent = false">收起</el-button>
    </div>
  </div>
</template>
```

**疑问**：
- 摘要截取长度多少合适？200字？ 可以的
- 是否需要支持 Markdown 渲染？肯定要的
- 长内容是否需要分页或虚拟滚动？
  - 我觉得可以用弹窗或者展开然后滚动, 不用分页, 如果评论很多就触底滚动就行

### 3️⃣ 评论功能完善
**当前状态**：前端存在静态内容，功能未完全实现

**需要实现的功能**：
- 评论的 CRUD 操作
- 点赞功能 (动态)
- 评论回复功能
- 评论的编辑/删除
- 评论的类型区分 (用户评论 vs AI 评论)

**疑问**：
- 评论是否需要权限控制？权限指的是? 先区分成员和 admin 就可以了, admin 可以删除所有, 成员可以编辑自己的
- 是否需要 @提及功能？需要的
- 评论是否支持附件？支持
- AI 评论是否应该禁止编辑，只允许回复？也可以编辑的

## 🤔 技术疑问

### 1. 数据库结构
```sql

tasks (id, content, ...)

-- 评论表结构是否需要调整？

```

### 2. 导入逻辑调整
**新的导入选项**：
- 导入为评论 (默认)
- 导入覆盖内容 (特殊场景)
- 导入为新任务

**用户交互**：
导入时是否需要用户选择导入方式？不需要, 默认导入为评论

### 3. 导出功能扩展
**导出内容**：
- 当前：仅导出任务基本信息和 content
- 新增：导出时包含评论历史

**导出格式**：
```markdown
# 任务详情
...

## AI 完成记录
### 评论 1 (2025/10/28)
内容...

### 用户反馈 (2025/10/28)
内容...
```

### 4. 前端组件影响

- `ImportTasks.vue` - 导入功能
- `ExportTasks.vue` - 导出功能
- `CommentList.vue` - 评论列表 (可能需要新建)

## ❓ 需要确认的问题

1. **历史数据处理**：现有任务如何处理？是否需要数据迁移？不用处理

2. **用户习惯**：用户是否适应新的工作流程？是否需要引导？不用,现在只有我一个用户, 还在开发阶段

3. **性能考虑**：评论很多时，加载和展示性能如何保证？分页加载, 触底加载更多

4. **权限设计**：不同用户对评论的操作权限如何设计？先区分成员和 admin 就可以了, admin 可以删除所有, 成员可以编辑自己的

5. **移动端适配**：长内容的"查看详情"在移动端如何优化？可以弹窗或者点击展开

6. 导出问题
   1. 如果没有评论, 正常导出标题, content 等其他任务基础信息
   2. 如果有评论, 导出时可以勾选评论, 然后导出评论历史, ai 评论通常很长,因此只要导出摘要, 不需要导出完整内容(所以评论可能还需要一个摘要字段)
