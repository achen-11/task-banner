# 数据库设计文档

## 一、设计原则

1. **不使用软删除**: 所有删除操作都是物理删除
2. **使用自增 ID**: 主键使用整型自增 ID
3. **时间戳字段**: 使用 UNIX 时间戳（整型）
4. **JSON 字段**: 对于复杂数据使用 JSON 存储
5. **外键约束**: 使用外键保证数据完整性

## 二、数据表设计

### 1. 用户表 (Users)

用于存储用户基本信息（认证由 Kooboo 内置功能处理）。

```csharp
public class User
{
    public int Id { get; set; }                    // 主键，自增
    public string Username { get; set; }           // 用户名，唯一
    public string Email { get; set; }              // 邮箱，唯一
    public string Avatar { get; set; }             // 头像 URL
    public string DisplayName { get; set; }        // 显示名称
    public int CreatedAt { get; set; }             // 创建时间（UNIX 时间戳）
    public int UpdatedAt { get; set; }             // 更新时间（UNIX 时间戳）
}
```

**索引**:
- `Username` (唯一索引)
- `Email` (唯一索引)

### 2. 项目表 (Projects)

```csharp
public class Project
```

### 4. 模块表 (Modules)

支持多级嵌套的模块结构。

```csharp
public class Module
{
    public int Id { get; set; }                    // 主键，自增
    public int ProjectId { get; set; }             // 项目 ID (外键 -> Projects.Id)
    public string Name { get; set; }               // 模块名称
    public string Color { get; set; }              // 模块颜色标识（HEX）
    public int ParentId { get; set; }              // 父模块 ID (0 表示根模块)
    public int Order { get; set; }                 // 排序字段
    public int CreatedAt { get; set; }             // 创建时间
    public int UpdatedAt { get; set; }             // 更新时间
}
```

**索引**:
- `ProjectId` (普通索引)
- `ParentId` (普通索引)
- `ProjectId, ParentId, Order` (复合索引，用于排序)

**外键约束**:
- `ProjectId` REFERENCES `Projects(Id)` ON DELETE CASCADE

**说明**:
- `ParentId = 0` 表示顶级模块
- `Order` 字段用于同级模块的排序

### 5. 任务表 (Tasks)

核心数据表，存储任务信息。

```csharp
public class Task
{
    public int Id { get; set; }                    // 主键，自增
    public string TaskId { get; set; }             // 任务唯一标识（UUID，用于前端）
    public int ProjectId { get; set; }             // 项目 ID (外键 -> Projects.Id)
    public int ModuleId { get; set; }              // 模块 ID (外键 -> Modules.Id, 0 表示无模块)
    public string Title { get; set; }              // 任务标题
    public string Content { get; set; }            // 任务内容（Quill.js Delta JSON）
    public string Status { get; set; }             // 状态: todo, in_progress, completed, sent_to_ai, needs_optimization
    public string Priority { get; set; }           // 优先级: low, medium, high, urgent
    public int AssigneeId { get; set; }            // 负责人 ID (外键 -> Users.Id, 0 表示未分配)
    public int CreatorId { get; set; }             // 创建人 ID (外键 -> Users.Id)
    public int DueDate { get; set; }               // 截止日期（UNIX 时间戳，0 表示无截止日期）
    public int Progress { get; set; }              // 进度 0-100
    public int Order { get; set; }                 // 排序字段
    public int CreatedAt { get; set; }             // 创建时间
    public int UpdatedAt { get; set; }             // 更新时间
}
```

**索引**:
- `TaskId` (唯一索引)
- `ProjectId` (普通索引)
- `ModuleId` (普通索引)
- `AssigneeId` (普通索引)
- `CreatorId` (普通索引)
- `Status` (普通索引)
- `ProjectId, Status, Order` (复合索引，用于看板排序)

**外键约束**:
- `ProjectId` REFERENCES `Projects(Id)` ON DELETE CASCADE
- `ModuleId` REFERENCES `Modules(Id)` ON DELETE SET NULL
- `CreatorId` REFERENCES `Users(Id)` ON DELETE CASCADE

**说明**:
- `TaskId` 是 UUID，用于前端唯一标识（兼容 task-banner）
- `Content` 存储 Quill.js 的 Delta 格式 JSON
- `AssigneeId = 0` 表示未分配负责人
- `ModuleId = 0` 表示未归属任何模块
- `DueDate = 0` 表示无截止日期

### 8. 任务历史表 (TaskHistory)

用于记录任务的所有变更，实现迭代历史功能。

```csharp
public class TaskHistory
{
    public int Id { get; set; }                    // 主键，自增
    public int TaskId { get; set; }                // 任务 ID (外键 -> Tasks.Id)
    public int UserId { get; set; }                // 操作用户 ID (外键 -> Users.Id)
    public string Field { get; set; }              // 变更字段名
    public string OldValue { get; set; }           // 旧值（JSON）
    public string NewValue { get; set; }           // 新值（JSON）
    public string Action { get; set; }             // 操作类型: create, update, delete
    public int CreatedAt { get; set; }             // 创建时间
}
```

**索引**:
- `TaskId, CreatedAt` (复合索引，用于按时间查询历史)
- `UserId` (普通索引)

**外键约束**:
- `TaskId` REFERENCES `Tasks(Id)` ON DELETE CASCADE
- `UserId` REFERENCES `Users(Id)` ON DELETE CASCADE

**说明**:
- 记录每次任务变更的详细信息
- `Field` 表示变更的字段名（如 "title", "status", "assignee"）
- `OldValue` 和 `NewValue` 存储 JSON 格式的值，便于展示

## 三、数据关系图

```
Users (用户)
  ├─ 1:N -> Projects (拥有的项目)
  ├─ N:M -> Projects (参与的项目，通过 ProjectMembers)
  ├─ 1:N -> Tasks (创建的任务)
  ├─ 1:N -> Tasks (负责的任务)
  ├─ 1:N -> TaskHistory (操作历史)
  ├─ 1:N -> TaskComments (评论)
  └─ 1:N -> Notifications (通知)

Projects (项目)
  ├─ 1:N -> Modules (模块)
  ├─ 1:N -> Tasks (任务)
  ├─ 1:N -> Tags (标签)
  └─ N:M -> Users (成员，通过 ProjectMembers)

Modules (模块)
  ├─ 1:N -> Modules (子模块，自关联)
  └─ 1:N -> Tasks (任务)

Tasks (任务)
  ├─ N:M -> Tags (标签，通过 TaskTags)
  ├─ 1:N -> TaskHistory (历史记录)
  └─ 1:N -> TaskComments (评论)
```

## 四、查询示例

### 1. 获取用户的所有任务（我的任务页面）

```sql
SELECT t.* FROM Tasks t
WHERE t.AssigneeId = ? OR t.CreatorId = ?
ORDER BY t.Order ASC
```

### 2. 获取项目的所有任务（列表视图）

```sql
SELECT t.*, u.DisplayName as AssigneeName
FROM Tasks t
LEFT JOIN Users u ON t.AssigneeId = u.Id
WHERE t.ProjectId = ?
ORDER BY t.Order ASC
```

### 3. 获取任务的完整信息（包括标签、评论数等）

```sql
SELECT
  t.*,
  u1.DisplayName as AssigneeName,
  u2.DisplayName as CreatorName,
  m.Name as ModuleName,
  GROUP_CONCAT(tg.Name) as Tags,
  COUNT(DISTINCT tc.Id) as CommentCount
FROM Tasks t
LEFT JOIN Users u1 ON t.AssigneeId = u1.Id
LEFT JOIN Users u2 ON t.CreatorId = u2.Id
LEFT JOIN Modules m ON t.ModuleId = m.Id
LEFT JOIN TaskTags tt ON t.Id = tt.TaskId
LEFT JOIN Tags tg ON tt.TagId = tg.Id
LEFT JOIN TaskComments tc ON t.Id = tc.TaskId
WHERE t.Id = ?
GROUP BY t.Id
```

### 4. 获取任务的迭代历史

```sql
SELECT h.*, u.DisplayName as UserName
FROM TaskHistory h
LEFT JOIN Users u ON h.UserId = u.Id
WHERE h.TaskId = ?
ORDER BY h.CreatedAt DESC
```

### 5. 获取模块树（递归查询）

```sql
-- 获取项目的所有模块，前端构建树
SELECT * FROM Modules
WHERE ProjectId = ?
ORDER BY ParentId ASC, Order ASC
```

## 六、性能优化建议

1. **索引优化**
   - 已为常用查询字段添加索引
   - 复合索引用于优化多条件查询和排序

2. **查询优化**
   - 使用 LEFT JOIN 替代子查询
   - 避免 N+1 查询问题
   - 分页查询使用 LIMIT + OFFSET

3. **数据清理**
   - 定期清理旧的通知记录（已读 > 30天）
   - 定期归档历史数据

4. **缓存策略**
   - 用户信息缓存
   - 项目成员列表缓存
   - 模块树缓存
