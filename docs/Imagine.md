# 创建项目
1.用户在 kb-task web 界面创建一个项目
2.kb-task 调用 claude cli 创建一个文件夹(沙盒/独立工作区), 这里可以做一些初始化, 比如:
    1.通过 kooboo-cli 同步创建一个远程站点;
    2.在文件夹中构建好基础结构, 如:
        1. 符合 kooboo-cli 的kooboo 的项目目录(用于通过 kooboo-cli sync 到远程站点)
        2. 前端项目(未打包前), 打包后的要通过 vite 和脚本放到 kooboo-cli 指定的文件同步到远程站点
3.到这一步算创建项目成功

# 对齐需求(其实也可以算做是任务, 只是需求讨论一般不涉及修改代码, 并且是在编辑代码之前, 我觉得有必要单拎出来)
1. 通过新增"文档"模块和"ai 对话", 让用户在 kb-task 的 web 界面来对齐需求
2. 对齐需求(应该包含项目的菜单, 功能, 页面, 数据库设计等)
3. 需求对齐后, ai 可以细分一些任务给用户, 用户可以选择添加为任务

# 任务进行
1. 有了任务之后, 用户可以在 kb-task 的 web 界面, 选择一个任务, 然后点击"让 ai 去执行"按钮
2. kb-task 携带上任务, 调用 claude cli 生成和完成任务
3. 完成任务后通过某些方式, 更新 kb-task 的任务状态, 通知客户任务完成, 可以验收

# 任务验收
1. 可以先降级, 让客户手动验收, 然后手动输入反馈
2. 后续再同意 browser-use 验证
