# 认证适配方案说明

## 问题背景

Kooboo 的认证依赖服务端的 `k.account` API 和 Cookie：

```javascript
// Kooboo 服务端代码（无法在本地执行）
if (!k.account.isLogin) {
  k.response.redirect('/_Admin/login?permission=u&returnurl=/')
  return
}
const userInfo = getUserInfo()
k.utils.clientJS.setVariable('__USER_INFO__', userInfo)
```

**本地开发的挑战**：
- ❌ 前端在 Vite 开发服务器运行，无法访问 `k.account` API
- ❌ 无法执行 `<script env="server">`
- ❌ 无法读取 Kooboo 的 Cookie
- ❌ 无法获取服务端注入的 `__USER_INFO__`

---

## 解决方案

实现了一个**环境自适应的认证适配层**，根据运行环境自动切换认证方式。

### 架构设计

```
┌─────────────────────────────────────────────────────┐
│                   认证适配层                          │
│                  (utils/auth.ts)                     │
├─────────────────────────────────────────────────────┤
│                                                       │
│  ┌─────────────────┐      ┌─────────────────┐      │
│  │   开发模式       │      │   生产模式       │      │
│  │  (DEV = true)   │      │ (DEV = false)   │      │
│  ├─────────────────┤      ├─────────────────┤      │
│  │ • Mock 用户数据  │      │ • k.account API │      │
│  │ • localStorage  │      │ • Cookie 认证   │      │
│  │ • 自动登录      │      │ • __USER_INFO__ │      │
│  │ • Bearer Token  │      │ • Kooboo 登录页 │      │
│  └─────────────────┘      └─────────────────┘      │
│                                                       │
└─────────────────────────────────────────────────────┘
```

## 核心文件

### 1. `utils/auth.ts` - 认证核心

提供环境自适应的认证 API：

```typescript
// 检查登录状态（自动适配环境）
export function isLogin(): boolean

// 获取当前用户（自动适配环境）
export function getCurrentUser()

// 开发模式登录
export function devLogin(username?, password?)

// 统一的退出登录（自动适配环境）
export function logout()

// 初始化认证（开发模式自动登录）
export function initAuth()

// 认证守卫（路由拦截）
export function requireAuth(): boolean
```

### 2. `utils/request.ts` - HTTP 请求工具

自动处理认证和错误：

```typescript
// 开发模式：自动添加 Bearer Token
// 生产模式：通过 Cookie 认证
import request from '@/utils/request'

const data = await request.get('/api/projects')
```

### 3. `router/guards.ts` - 路由守卫

自动检查认证状态：

```typescript
router.beforeEach((to, from, next) => {
  if (to.meta.requiresAuth !== false) {
    if (requireAuth()) {
      next()
    }
  }
})
```

## 使用示例

### 场景 1: 页面组件中使用

```vue
<script setup lang="ts">
import { getCurrentUser, isLogin } from '@/utils/auth'
import { ref, onMounted } from 'vue'

const user = ref(null)

onMounted(() => {
  if (isLogin()) {
    user.value = getCurrentUser()
  }
})
</script>

<template>
  <div>
    <p>当前用户: {{ user?.displayName }}</p>
  </div>
</template>
```

### 场景 2: API 请求

```typescript
import request from '@/utils/request'

// 自动处理认证
const projects = await request.get('/api/projects')

const newProject = await request.post('/api/projects', {
  name: 'Project Name'
})
```

### 场景 3: 路由配置

```typescript
{
  path: '/dashboard',
  component: Dashboard,
  meta: {
    requiresAuth: true  // 需要认证（默认）
  }
},
{
  path: '/public',
  component: PublicPage,
  meta: {
    requiresAuth: false  // 不需要认证
  }
}
```

### 场景 4: 退出登录

```typescript
import { logout } from '@/utils/auth'

const handleLogout = () => {
  logout()  // 自动适配环境
}
```

## 生产环境配置

### 服务端注入用户信息

**重要**：服务端脚本已通过 Vite 构建插件自动注入到 `index.html` 中，无需手动添加。

构建后的 HTML 会自动包含：

```html
<!-- @k-url / -->
<!DOCTYPE html>
<html lang="">
  <head>
    <title>Task Flow</title>

    <!-- 服务端脚本：检查登录状态并注入用户信息 -->
    <script env="server" type="module">
      import { getUserInfo } from './Services.user'

      // 1. 检查登录状态
      if (!k.account.isLogin) {
        k.response.redirect('/_Admin/login?permission=u&returnurl=/')
        return
      }

      // 2. 获取当前登录用户
      const username = k.account.user.current.userName
      const userInfo = getUserInfo(username)

      // 3. 注入用户信息到客户端
      k.utils.clientJS.setVariable('__USER_INFO__', userInfo)
    </script>
    <script type="module" crossorigin src="/index-[hash].js"></script>
  </head>
  <body>
    <div id="app"></div>
  </body>
</html>
```

**实现细节**：
- Vite 插件 `addKoobooUrlPlugin()` 在构建时自动注入服务端脚本
- 服务端脚本在 Kooboo 运行时执行，Vite 构建时不处理
- 用户服务位于 `code/Services/user.ts`

### API 退出登录

```javascript
// Api: __logout__
k.account.logout()
k.cookie.clear()
k.response.redirect("/_Admin/login?permission=o&returnurl=/")
```

## 认证流程对比

### 开发模式流程

```
1. 应用启动
   ↓
2. initAuth() 检查 localStorage
   ↓
3. 无 token → 自动调用 devLogin()
   ↓
4. 存储 Mock 用户到 localStorage
   ↓
5. 后续请求自动添加 Bearer Token
```

### 生产模式流程

```
1. 访问应用
   ↓
2. 服务端检查 k.account.isLogin
   ↓
3. 未登录 → 重定向到 /_Admin/login
   ↓
4. Kooboo 登录成功 → 返回应用
   ↓
5. 服务端注入 __USER_INFO__
   ↓
6. 前端从 window.__USER_INFO__ 获取用户
   ↓
7. 后续请求通过 Cookie 认证
```

## API 对照表

| 功能 | 开发模式 | 生产模式 |
|------|---------|---------|
| **登录检查** | `localStorage.getItem('dev_token')` | `window.__USER_INFO__` |
| **获取用户** | `JSON.parse(localStorage.getItem('dev_user'))` | `window.__USER_INFO__` |
| **登录** | `devLogin()` → localStorage | Kooboo 登录页 |
| **退出** | `localStorage.clear()` → reload | 重定向到 `/__logout__` |
| **认证方式** | `Authorization: Bearer token` | Cookie |
| **路由拦截** | 自动登录 Mock 用户 | 重定向到 Kooboo 登录页 |

## 优势

✅ **开发体验**：无需启动后端，Mock 数据即可开发
✅ **代码统一**：同一套代码适配两种环境
✅ **类型安全**：TypeScript 完整支持
✅ **自动切换**：根据环境自动选择认证方式
✅ **零配置**：开发时自动登录，无需手动操作
✅ **生产就绪**：无缝对接 Kooboo 认证系统

---

## 注意事项

1. **不要在生产环境调用 `devLogin()`**，它只在开发模式工作
2. **使用统一的 `logout()` 方法**，而不是直接操作 localStorage
3. **路由默认需要认证**，公开页面需要设置 `requiresAuth: false`
4. **API 请求使用 `request` 工具**，不要直接使用 axios
5. **用户信息通过 `getCurrentUser()` 获取**，不要直接访问 localStorage 或 window

这个认证适配方案完美解决了本地开发无法使用 Kooboo 认证的问题，同时保持了代码的简洁和统一。开发者无需关心环境差异，只需使用统一的 API 即可。
